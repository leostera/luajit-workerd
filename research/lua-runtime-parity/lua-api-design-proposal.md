# Draft proposal: Lua-facing workerd host APIs

- **Status:** Proposal for discussion; none of these APIs are accepted or implemented by this document.
- **Source snapshot:** workerd `9f79d373b08a52f7865cfdfeaedf68f15cd4efec`, audited 2026-10-14.
- **Scope:** Propose idiomatic Lua contracts for the 20 JSG families classified `BL` in [feature-matrix.md](feature-matrix.md). This is host-capability design, not a port of JavaScript, V8, Node.js, or JSG semantics.
- **Related notes:** [architecture.md](architecture.md) for the current Lua host boundary; [final-audit.md](final-audit.md) for implementation and verification gaps.

## Proposal in brief

Expose configured workerd capabilities as ordinary Lua tables and opaque handles, under `workerd` or `workerd.bindings`. Use Lua's colon-call convention for capability methods, Lua tables for structured values, binary-safe strings for bytes, and request-coroutine yielding for asynchronous host I/O. Operational failures raise catchable Lua errors; an absent resource is represented by `nil` where that is a normal result. Streams, database connections, sockets, actors, and processes are opaque handles with explicit lifetimes rather than JavaScript objects or raw KJ types.

Keep the existing module return shape and `fetch(request)` signature. Add event/actor exports only as named fields alongside `fetch`, never as `env` or `ctx` arguments. Keep all routing, storage, and egress host-mediated. Lua remains experimental and trusted-code-only.

This proposal chooses an initial direction for every unimplemented family, but deliberately leaves acceptance gates on the response-body contract, actors/resource accounting, production policy injection, dynamic code loading, and security-sensitive network/filesystem access. It is a starting design to review—not authorization to change those contracts.

## Invariants and common Lua contract

### Existing handler remains intact

The current worker continues to return:

```lua
return {
  fetch = function(request)
    return { status = 200, headers = {}, body = "ok" }
  end,
}
```

`fetch` keeps one `request` argument. No `env` or `ctx` argument is added. A worker using only HTTP remains valid when new optional exports or bindings are introduced.

### Lua-native values and errors

- Call capability methods with `:` (for example, `bucket:get(key)`) and options as a final table.
- Use Lua strings for binary data. Use tables for records and arrays. Use `workerd.null` when an explicit null must differ from an absent table field.
- Return `nil` for an ordinary miss (for example, cache/KV/R2 lookup). Raise a catchable Lua error for configuration, transport, policy, cancellation, or malformed-result failures. Do not encode failures as JavaScript `Response` values or Promise rejections.
- Host I/O called from a worker coroutine suspends that coroutine and resumes it with a result or error. Lua sees ordinary function calls, not Promise objects. Pure local operations such as clock reads do not yield.
- Use request-scoped opaque handles for streams, cursors, sockets, and WebSockets. Handles expose explicit `close()`/`cancel()` and are invalid after request/event completion. They cannot be saved in mutable service-global state for later requests.
- Keep input types and size limits explicit. Reject unknown options rather than silently ignoring them. Apply admission, quota, cancellation, tracing, and accounting in host adapters before/around the linked service call.
- Do not expose ambient `kj::Network`, raw channels, `IoContext`, V8/JSG values, or direct host paths as the Lua API.

### Streaming prerequisite

The current handler response requires a string body, capped at 1 MiB. The proposed `workerd.stream.producer(function() return chunk_or_nil end)` would create a request-scoped stream handle; the host pulls it only when downstream is ready, and `nil` marks EOF. Run the producer as a managed child Lua coroutine so it can call yielding host APIs; do not invoke a yieldable function inside a non-yieldable C callback. Accept that handle as a response `body` alongside existing strings and inbound/outbound stream handles. On downstream cancellation or producer error, cancel the producer and all work it owns. **Do not implement handler response streaming without explicit user approval.** This shared stream contract is a prerequisite for idiomatic Cache, R2, HTML rewriting, and container I/O; until then those adapters must remain bounded or unavailable rather than hiding buffering.

## Proposed Lua surfaces

The names below are proposed names, not existing APIs. `workerd.bindings.NAME` means the capability is explicitly configured and linked by the host.

| Family | Proposed Lua surface | Proposed semantics and prerequisites |
| --- | --- | --- |
| `durable-objects` | Module may add `actors = { Counter = function(state) return { fetch = ..., alarm = ... } end }`. A configured namespace exposes `workerd.bindings.COUNTER:idFromName(name)` and `:get(id)`, returning a stub with `:fetch(request)`; typed `:call(method, value)` is a later RPC layer. | Use a factory/table-of-functions, not JS classes or inheritance. Give each actor object its own Lua state so globals and coroutines cannot leak between object IDs; host storage, not Lua globals, is durable. Preserve serialized per-object execution and actor eviction/restart rules. This is a major runtime/memory-accounting prerequisite: do not emulate actors as entries in the service-global HTTP Lua state. |
| `durable-objects-state` | The actor factory receives one actor-specific `state` capability. `state.id`; `state.storage:get/put/delete/list`; `state.storage:transaction(function(tx) ... end)`; `state.storage:setAlarm(time)` and `:getAlarm()`. | Storage calls yield in the actor coroutine. Transaction callbacks receive a transaction-only `tx` object; only operations on that transaction may run inside the callback, and transaction handles cannot escape or continue after rollback. Do not permit unrelated network/service calls while a transaction is open. The host either commits completely or raises. Define limits, serialization, consistency, alarm retries, migration, restart, cancellation, and transaction yield semantics before implementation. Depends on the actor VM/lifecycle proposal. |
| `analytics-engine` | `workerd.bindings.ANALYTICS:writeDataPoint({ indexes = {...}, blobs = {...}, doubles = {...} })`. | Accept only an explicit table schema; validate field counts/types and configured limits before dispatch. Return no value on accepted write; failures raise. The host owns write accounting and retry semantics. Decide batch support separately; do not serialize arbitrary Lua tables. |
| `cache` | `workerd.cache.default:match(request)`, `:put(request, response)`, and `:delete(request)`. A named cache, if needed, is `workerd.cache:open(name)` after host configuration permits it. | Cache is a host service, not a second `globalOutbound` route. A miss returns `nil`; a hit returns a response table with status, headers, and a request-scoped body handle. Define cache statuses, key normalization, vary behavior, expiration, revalidation, body ownership, and write limits. Requires configured Cache channel and response streaming decision. |
| `html-rewriter` | `workerd.html.rewrite(response, { ["a[href]"] = { element = function(el) ... end } })`; element methods are `:getAttribute`, `:setAttribute`, `:removeAttribute`, and `:setInnerContent`. | Parse and transform as a streaming host operation. Element callbacks are synchronous and may mutate only the current element; they must not yield or retain the element after callback return. This avoids yielding through parser C frames. Rewriter output is a stream handle, so this depends on an approved streaming response contract. Specify selector errors, encoding, malformed HTML, cancellation, and transformation limits. |
| `hyperdrive` | `local db = workerd.bindings.DB:connect()` returns an opaque, host-authorized byte-stream connection; `db:read(maxBytes)`, `:write(bytes)`, and `:close()`. A configured Lua SQL-driver library implements the wire protocol. | Do not expose connection strings/passwords or raw sockets. The host selects the Hyperdrive target, handles credentials/TLS/pooling policy, and accounts for the connection. Define connect timeouts, connection lifetime, byte limits, retries, and cancellation. Reuse the socket stream contract but restrict destinations to the configured Hyperdrive service. |
| `memory-cache` | A configured cache namespace exposes `workerd.bindings.MEMORY_CACHE:get(key)`, `:put(key, value[, { ttl = seconds }])`, and `:delete(key)`. | Values are binary strings; a miss returns `nil`; TTL and key/value limits are explicit. Start with service/process-scoped namespaces and no cross-process persistence claim. Specify worker isolation, eviction, consistency, maximum size, and quota. Do not alias it to `workerd.cache` or Durable Object storage. |
| `queue` | Producer: `workerd.bindings.EVENTS:send(value[, options])` and `:sendBatch(values[, options])`. Optional module export: `queue = function(batch) return { ack = {...}, retry = {...} } end`, where outcome arrays contain message IDs. | Initially accept only JSON-compatible Lua values or binary strings with explicit content type; reject functions, metatables, cycles, and userdata. Consumers receive a batch with IDs, timestamps, and decoded body values. The host applies ack/retry outcomes per message after handler completion; a thrown error retries the unacknowledged batch according to queue policy. Define limits, visibility/lease time, retry delay, batch concurrency, and cancellation. Event export is additive to `fetch`, but needs lifecycle approval. |
| `r2` | `workerd.bindings.BUCKET:get(key[, options])`, `:put(key, body[, options])`, `:head(key)`, `:delete(key)`, and `:list(options)`. `get` returns `nil` or `{ body = stream, size = ..., etag = ..., httpMetadata = ..., customMetadata = ... }`. | Metadata is a Lua table; object bodies are opaque streams; writes accept bounded strings or approved producer streams. Missing objects return `nil`. Start with get/put/head/delete/list; defer multipart until resource/abort semantics are designed. Define conditional operations, ranges, metadata limits, pagination, byte caps, cancellation, and R2 accounting. Requires streaming and a configured bucket capability. |
| `worker-rpc` | A configured service exposes `workerd.bindings.CALCULATOR:call("add", { left = 1, right = 2 })`; direct known methods may later be sugar over `call`. | Initial value domain: nil/boolean/finite number/string/table with string or integer keys; no functions, cycles, streams, or transferable capabilities. Calls yield and return a Lua value. Remote exceptions become catchable Lua errors with remote service/method context. Keep this distinct from `.fetch(request)` and define serialization versioning, depth/size limits, recursion and accounting. |
| `scheduled` | Add optional `scheduled = function(event) ... end`; event fields are `scheduledTime` (Unix milliseconds) and `cron`. `fetch(request)` is unchanged. | Handler success completes the event; a thrown error reports failure to the host retry policy. No implicit background tasks or `waitUntil` in v1. The event gets its own request scope, trace, cancellation, and observer lifetime. Specify concurrent access to service-global Lua state, maximum duration, retry behavior, and shutdown before registering the export. |
| `websocket` | `fetch` may return the explicit variant `{ websocket = { message = function(socket, bytes) ... end, close = function(socket, code, reason) ... end } }`. The host performs the 101 handshake. `socket:send(bytes)`, `:close(code, reason)`, and `:protocol()` operate on an opaque handle. | This is an additive handler-result variant; existing HTTP response tables remain unchanged. The host invokes one message callback at a time with `{ kind = "text"|"binary", data = bytes }` and awaits its coroutine before delivering the next message, providing bounded backpressure. Callback errors close with an internal-error code and are logged; disconnect cancels the callback. Define message-size/queue limits, binary/text representation, ping/pong, close validation, and request/event lifetime. Requires WorkerInterface upgrade support and explicit contract approval. |
| `sql` | Only on actor state: `state.storage.sql:exec(query, ...)` returns a cursor with `:next()` and `:close()`. Bind parameters are positional Lua values; each row is a name-keyed Lua table. | Keep SQL separate from Hyperdrive: this is actor-local SQLite storage with actor transaction/consistency semantics. Cursor reads yield only if the host storage operation does; cursors are transaction-bound and request-scoped. Define SQL type conversion, statement limits, row/byte caps, transaction ownership, and close-on-cancel. Depends on Durable Object storage design. |
| `sockets` | A configured egress capability exposes `workerd.bindings.NET:connectTcp(host, port[, options])` and `:connectUdp(host, port[, options])`; returned handles provide `:read`, `:write`, `:receive`, `:send`, and `:close`. | Never enable arbitrary LuaJIT OS/LuaSocket networking as the workerd capability. Enforce destination/port policy, DNS rules, connection counts, byte/time limits, and accounting before dispatch. Reads/writes yield and honor backpressure; UDP retains datagram boundaries. Define TLS separately; do not silently imply TLS from TCP. Requires provider egress-policy injection and security review. |
| `container` | A configured binding exposes `local process = workerd.bindings.BUILD:exec(argv[, options])`; the process has `stdout` and `stderr` stream handles plus `process:wait()` and `process:kill()`. | `argv` is an argument array, never a shell string. Container lifecycle is host-owned; Lua can request work and observe exit status but cannot escape configured image, filesystem, network, or resource limits. Define reuse/ownership, concurrency, CPU/memory/time budgets, env/secrets, cancellation, output caps, and shutdown. The current workerd configuration couples containers to actor/container integration; decide whether Lua containers are actor-scoped or separately scoped. Actor support alone is not sufficient. |
| `webfs` | A configured root exposes `workerd.bindings.FILES:open(path, mode)` returning a file handle with yielding `:read`, `:write`, `:stat`, and `:close`; `:list(path)` is paginated. | Paths are relative to a configured root; reject traversal, absolute paths, and symlinks escaping the root. File handles are request-scoped. The host enforces read/write permissions, byte quotas, and cancellation. Define atomic writes, rename/delete, directory behavior, and whether this managed store adds value while trusted Lua's standard filesystem library remains open. Never market it as a Lua sandbox. |
| `sync-kv` | **No synchronous API in the proposal.** Keep `workerd.bindings.KV:get()` coroutine-yielding. | Blocking remote calls can stall the event loop and defeat fairness/cancellation. Reconsider only for a demonstrated local/cached case with explicit bounded latency and no network access. Prefer classifying it as an intentional non-goal over emulating JS synchronous KV. |
| `worker-loader` | `workerd.bindings.LOADER:load("predeclared-name")` returns a handle exposing `:fetch(request)`; names map to worker code/config already declared by the host. | V1 must not accept source text, arbitrary bindings, or caller-selected filesystem paths. Predeclared targets keep trust and capability grant with operator configuration. Dynamic source loading remains out of scope until provenance, isolation, resource limits, lifecycle, cache/reuse, and explicit trust-boundary approval are resolved. This is narrower than general Worker Loader parity. |
| `performance` | `workerd.performance.now()` returns monotonic milliseconds from the invocation's workerd `TimerChannel`; `timeOrigin` is omitted initially. | Runtime-neutral host operation only; never call `kj::Timer` directly. Keep the clock Spectre-mitigated and timeout-clamped like the standard request path. Specify precision and consistency with `workerd.sleep()`; test monotonicity and that no cross-request timer handle escapes. |
| `tracing` | `workerd.tracing.withSpan(name, attributes, function(span) ... end)`; `span:setAttribute`, `span:addEvent`, and `span:recordError` are available only during the callback. | The host creates a child span under the request parent, runs the callback in the same Lua coroutine (which may yield at host operations), closes the span on all exits, marks thrown errors, and rethrows them. Span handles cannot escape the callback or request. Define attribute types/limits and observer/metrics policy; do not expose KJ span objects. |

## Configuration, lifecycle, and operational design

The configuration matrix has additional rows that do not map one-to-one to JSG families. These decisions prevent service/config behavior from being mistaken for API parity.

| Configuration/service row | Proposed Lua contract or explicit disposition |
| --- | --- |
| Handler response-body streaming | Accept `body = workerd.stream.producer(...)` as an additive response-body variant beside existing strings. Preserve the 1 MiB string limit. Requires explicit user approval, response backpressure/cancellation semantics, and server disconnect tests before implementation. |
| Asynchronous Lua-generated bodies | Outbound request-body producers now run in a host-managed child coroutine, are pulled only on demand, and may yield through existing host operations; cancellation and byte limits remain tied to the request. This does not alter the handler response contract. Streaming handler response bodies still require explicit approval, response backpressure/cancellation semantics, and server disconnect tests before implementation. |
| Cache API outbound route | Expose `workerd.cache.default` through a separately linked Cache capability. Do not alias it to `globalOutbound` or `workerd.fetch()`. Cache policy, namespace, and body limits come from configuration/host policy. |
| Durable Object, R2, Queue, Analytics, Hyperdrive bindings | Use the per-family interfaces above. Each binding is parsed and linked at service construction; runtime Lua receives a typed capability, not a URL or raw channel. Reject unsupported binding types before serving. |
| Parameter/inheritance bindings | Do not implicitly merge inherited Lua workers or inject a generic `env`. If a use case needs immutable configuration values, add a typed `luaParameters` config and expose a startup snapshot as `workerd.parameters`; keep service bindings separately under `workerd.bindings`. Defer parent-worker inheritance until precedence, source ownership, and service-state lifetimes are specified. |
| Wrapped binding | Do not run the current JS `env` wrapper around Lua bindings. If wrappers are needed, define a language-neutral host-side capability decorator (policy/validation/metrics) before Lua module evaluation; otherwise keep this internal binding unavailable to Lua. |
| Unsafe-eval, memory cache, Worker Loader, debug port | Keep unsafe-eval as no added capability; Lua's trusted-code status does not justify more dynamic loading. Expose memory cache and the restricted, predeclared Worker Loader only through the separate designs above. V8 debug-port semantics are not applicable; any Lua debugger must be a separate development-only design. |
| Module fallback/extensions | Retain one configured Lua chunk and the returned handler table. Do not load JS ESM/CJS or V8 extensions as Lua modules. A future multi-file loader must define Lua `require`/package roots, code provenance, caching, startup errors, and native-module policy independently. |
| Inheritance/derived workers | No implicit service inheritance in the first design. Prefer explicit configuration and named bindings; revisit only with clear merge rules for source, bindings, and the service-global Lua state. |
| Scheduled events | Optional `scheduled(event)` export; event receives its own scope/trace/cancellation, returns success or raises for retry policy. No implicit `waitUntil`. Specify maximum duration, retry ownership, and overlap with HTTP requests first. |
| Durable Object namespaces/storage, alarms, uniqueness | Use the actor factory, per-object Lua state, stub, and actor `state` capability above. IDs and uniqueness are host-generated/validated. Alarm callback is optional on the actor table and uses actor storage's alarm API; it is not a service-global timer. |
| Workflows | Optional `workflow = function(event) ... end` plus a configured `workerd.bindings.FLOWS:create(id, input)` capability. Each instance has host-owned durable state and explicit `step(name, fn)`/retry records; no automatic reuse of actor storage or `waitUntil`. Defer until workflow checkpoint, replay/idempotency, timeout, and cancellation semantics are designed. |
| Tail and streaming tail workers | Optional `tail = function(batch) ... end` receives bounded, redacted event records from a separate observer context; it cannot recursively generate tail events. Preserve delivery backpressure and shutdown; define access controls, log/trace schemas, redaction, batching, and drop policy before exposure. |
| Access metadata/binding | Add an optional immutable per-request `request.access` snapshot only when supplied by an authenticated host Access context; never derive identity from user headers or `request.cf` JSON. Define provenance, absent/invalid behavior, and field-level redaction. Do not provide a generic secret-bearing identity binding. |
| Container engine/DO containers | Use the configured `BUILD:exec(argv)` process capability above. Choose actor-scoped versus service-scoped lifecycle explicitly, and rely on host-enforced image, filesystem, egress, and resource policies. Depends on container engine availability and security review. |
| Worker Loader dynamic worker creation | V1 only loads operator-predeclared names via `LOADER:load(name)`; it does not accept source text or caller-supplied capabilities. Arbitrary dynamic code remains outside scope until trust, isolation, resource, and unload semantics receive explicit approval. |
| Runtime logs, metrics, tracing | Keep `workerd.tracing.withSpan()` from the family design. Add `workerd.log:write(level, fields)` and `workerd.metrics:record(name, value, labels)` only through request-scoped host interfaces with structured bounded fields, redaction, and sampling. Errors continue to be catchable Lua errors; the server logs uncaught failures. Production provider injection must be verified separately. |
| Inspector, DevTools, compile cache, heap/GC diagnostics | No V8 inspector/compile cache/heap API. Consider a Lua-specific local debugger and Lua-state allocator/GC diagnostics independently; do not expose a V8-compatible debug port. |
| Runtime resource enforcement | First meter Lua allocations with a per-state allocator and establish per-service memory ceilings. Investigate a sound LuaJIT instruction/time budget that remains effective with JIT enabled; until verified, make no hard CPU-quota or preemption claim. A synchronous infinite loop remains a deployment risk under trusted-code-only status. |

### Lifecycle and correctness contracts

| Concern | Proposed disposition |
| --- | --- |
| Request body | Keep buffered string as the default; retain opt-in bounded `request.bodyStream`. Each handle belongs to one request and closes on completion/cancellation. |
| Response body | Keep string results unchanged; consider the stream-producer variant only after explicit approval. Enforce demand-driven backpressure, byte limits, exactly-once close, and disconnect cancellation. |
| Headers | Preserve ordered `{name, value}` arrays so duplicate headers survive. Validate through workerd's HTTP header table; never coerce invalid bytes or merge duplicates implicitly. |
| Lua state ownership | Keep one VM per HTTP service and one coroutine per invocation; serialize VM access on its event-loop thread. Stateful actors, if accepted, get distinct per-object VMs rather than sharing service globals. |
| Async bridge | Retain typed host-operation descriptors, one resume per completion, cancellation cleanup, and request-local handles. No KJ/V8/JSG pointer crosses into Lua; no promise object is exposed. |
| Errors and observability | Preserve source-aware Lua errors. `pcall` can catch host errors; uncaught errors fail the request and are logged. Child spans/logs/metrics are request-scoped and torn down on success, error, or cancellation. |
| Compatibility and rollout | Keep `--experimental`; do not reuse JS compatibility dates/flags. If Lua APIs need stable evolution, introduce a Lua-specific `luaApiVersion` only when there is a demonstrated breaking-change need; otherwise additive APIs remain the default. |
| Tests/build | Maintain the runtime/server/I/O test split: Lua value and coroutine tests, service-link/config tests, host cancellation/admission/tracing tests, then relevant Bazel build/test and formatting checks. A passing standalone test does not establish Cloudflare provider wiring. |

This proposal does not imply all 20 capabilities should be implemented. Order work by use case and prerequisite, not by the JSG list:

1. **Settle the shared async/resource contract:** yielding host calls, handle ownership, cancellation, error mapping, and policy hooks. Verify provider-specific request/KV admission and observer/metrics injection separately.
2. **Design bounded data bindings:** Analytics Engine, memory cache, and narrow Cache/R2 operations. Agree on binary values, metadata tables, limits, and list cursors. Cache/R2 operations that return streams wait for the response-streaming decision.
3. **Design networking and integrations together:** host-mediated sockets first; then Hyperdrive as a restricted destination using the same opaque stream contract. No raw networking.
4. **Design additive event variants:** scheduled and queue consumers; WebSocket as a separate HTTP result variant. Specify completion, retry, concurrency, and cancellation as a family.
5. **Make explicit lifecycle/security decisions:** actors and actor state first, then SQL and any actor-backed container model. Decide resource accounting before creating per-object Lua states.
6. **Restrict dynamic capabilities:** predeclared Worker Loader names and root-scoped webfs only; arbitrary source loading or ambient filesystem/network access requires separate approval.
7. **Keep non-goals explicit:** sync-KV stays out unless a local nonblocking use case is demonstrated.

For every implementation, add a Lua API test, host-adapter test, server configuration/routing test, cancellation/limit test, and tracing/accounting test. Standalone unrestricted/no-op policy tests do not establish production enforcement.

## Implementation order

This proposal does not imply all 20 capabilities should be implemented. Order work by use case and prerequisite, not by the JSG list:

1. **Extend the shared async/resource contract:** request-scoped coroutine-yielding host calls, producer backpressure, ownership, cancellation, and catchable errors are implemented for the current HTTP surface. Verify provider-specific request/KV admission and observer/metrics injection separately.
2. **Design bounded data bindings:** Analytics Engine, memory cache, and narrow Cache/R2 operations. Agree on binary values, metadata tables, limits, and list cursors. Operations that return streams need the response-streaming decision only if they change the handler response contract; outbound request/response streams remain distinct.

## Costs, alternatives, and unresolved acceptance gates

- **Why Lua tables/handles instead of mirroring Web APIs?** This preserves Lua idioms and avoids fake JSG objects. The cost is defining and documenting separate value/stream contracts for Lua.
- **Why host capabilities instead of raw LuaJIT libraries?** Raw sockets/filesystem calls bypass workerd routing, quotas, cancellation, tracing, and managed-storage semantics. The cost is maintaining runtime-neutral host adapters and policy tests.
- **Why named event exports instead of separate JS-shaped handler arguments?** They preserve `fetch(request)` and avoid `env`/`ctx`, but create a module-export and concurrency contract that must be reviewed before events ship.
- **Why no general Worker Loader or sync-KV API?** Dynamic source loading widens trust/capability grants; synchronous remote I/O blocks the event loop. Narrower configured targets and asynchronous KV are safer defaults.
- **Response-streaming approval:** The `body = stream` proposal changes the current handler result contract. It remains unapproved and must not be implemented until the user accepts the contract and ownership/cancellation semantics.
- **Trusted-code boundary:** This proposal does not turn Lua into a sandbox. Dynamic source, filesystem and egress capabilities remain host-controlled and require security review.
- **Production parity:** The implementation must identify where Cloudflare-specific providers inject quotas, observers, and tracing. Standalone tests cannot close that gate.
- **Demand:** Choose representative Lua workloads and rank capabilities before committing to the full surface. These sketches show a coherent direction, not a promise to ship all 20 families.
